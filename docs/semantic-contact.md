# LCH GH-22 — Donna Semantic Contact

## Why
A real production browser submission failed with `Missing contact integration configuration: projectId`. The static Vite bundle had been compiled without Firebase's seven public SDK configuration values. The error happened before any Firestore write.

The immediately published Firebase-configured recovery build returned HTTP 200 from Firestore and a contact receipt on `https://lch-app.cloud`. This restores persistence, **not** Microsoft 365 sales notifications.

## Product UX
Donna can prepare the **same fields that Contact actually accepts**, without looking at HTML or automating browser clicks. The contract is exported from `src/contact/semanticContract.ts` under tool name `prepare_lch_contact_form`.

| Field | Source | Behavior |
| --- | --- | --- |
| nombre, apellido | Explicit introduction or guided answer | Partial if only one was supplied |
| email | Exact email in conversation | Validated, lowercased, never fabricated |
| empresa | Explicit organization/company | Missing stays empty |
| cargo | Explicit position or guided answer | Missing stays empty |
| interes | Clear business topic / previous grounded interest | Existing six-area enum |
| mensaje | User-stated business goal or question | Personal contact metadata is stripped when possible |
| consentimiento | **Never an assistant field** | Human checkbox, defaults unchecked |

The form's semantic labels, `name` attributes, length limits and business enums are reflected by this typed contract. The tool never offers `submit`, `telefono`, arbitrary DOM paths or `consentimiento`.

### Flows
- **One-sentence intake:** visitor says `Me llamo Ana Perez, soy directora de operaciones, trabajo en Acme y necesito automatizar facturas, mi correo es ana@acme.com`. Donna recognizes explicit fields locally, asks if any required field is missing, and offers a review step.
- **Guided intake:** visitor clicks `Donna, ayúdame a preparar una solicitud`. Donna asks one missing item at a time. This is local structured slot interpretation; no network calls for collection.
- **Existing chat → contact:** `Continuar con una persona` transfers the typed proposal, preserving human-edited fields. The existing chat API remains the same when answering ordinary business questions.
- **Review and consent:** the React contact form receives only allowed fields; the user can edit every value and must manually tick the existing consent checkbox and click `Quiero conversar con LCH`. Only then can Firestore create a lead.
- **Error path:** if a write fails, the form keeps values and shows the error. A receipt is shown only after Firestore confirms the write.

## Implementation boundaries
```text
DonnaChat (bounded local schema parser)
  ├── conversation/product questions ──> existing same-origin /api/chat
  └── prepare_lch_contact_form (React memory only)
      ├── semanticContract.ts + semanticDraft.ts
      └── ContactHandoff (typed props, no DOM scraping)
          └── Contact (review + manual consent + explicit submit)
              └── Firestore demoRequests (durable)
                  └── private n8n lead processor (existing; email notification NOT wired)
```

No new API keys, model provider, MCP UI iframe, DOM browser automation, data migrations or public n8n webhook. This is **schema-driven deterministic slot filling with a guided interaction**, not an LLM pretending to understand arbitrary prose. The contract is ready for a future server-mediated, consent-reviewed tool-calling model should the business choose to add one.

## Future LLM integration
If a generative model is later enabled, make it produce `PREPARE_CONTACT_TOOL.inputSchema`-conformant JSON, validate with `normalizeContactDraft`, return only proposed fields, and explicitly require user review. Never grant tool access to `consentimiento` or Firestore. Do not send prospect PII to an external provider without a privacy/governance decision.

## Production release guard
`npm run build` and `npm run build:deploy` now both validate all required build-time `VITE_CONTACT_*` parameters before Vite is invoked. `.env.production.local` remains ignored and has permission 600. Never ship an artifact generated by direct `vite build` outside this guarded workflow.
