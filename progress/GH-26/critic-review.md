# GH-26 | Adversarial n8n lead-mail architecture review

## Observed defects, mitigations and blockers

1. **HIGH — missing HTTPS origin in Firestore REST claim (FIXED).** Initial workflow used the relative Firestore resource path `projects/.../documents/...` as n8n's HTTP Request URL. Native Firestore query returns that path, but HTTP Request requires a fully qualified URL. Added fixed vendor prefix `https://firestore.googleapis.com/v1/` to claim, refresh and ACK nodes. Automated assertions now verify all three URLs.
2. **HIGH — duplicate mail on concurrent scheduling (MITIGATED).** Firestore conditional REST `PATCH` uses `currentDocument.updateTime` optimistic CAS and updates **only notification**. A concurrent workflow that loses the lease will fail before Outlook sends. Note: if Outlook accepts a message and the ACK write fails, a later retry can still duplicate. `x-lch-lead-id` allows investigation. This is not exactly-once delivery.
3. **HIGH — accidental historic-lead blast (FIXED).** Activation UTC Code node deliberately contains an invalid placeholder and returns zero items until an administrator sets an exact UTC cutoff. Only Firestore `createdAt` server-timestamped records newer than cutoff may be considered. The workflow remains INACTIVE and no provider credentials are attached.
4. **HIGH — sender authority (BLOCKED for production).** Outlook must be configured with an authenticated identity authorized to send as `contacto@lch-technologies.com`; the server has zero stored credentials. Do not grant broad tenant-wide application `Mail.Send`, and do not paste client secrets into workflow code or Git.
5. **HIGH — Firestore IAM and visitor privacy (BLOCKED for production).** Google service account must have limited access to the named Firestore database for query and conditional `notification` writes; client Firestore rules must not be relaxed. HTML escaping and exact To-recipient constant guard prevent arbitrary destinations or markup injection by the visitor.
6. **MEDIUM — n8n process reliability (BLOCKED for production).** The existing `n8n-lina` container was stopped after workstation recreation. It was recovered without changing Lina's workflow, but no verified persistent autostart / high-availability health monitoring exists for this email duty. Production activation requires restart resilience. No n8n editor ingress was enabled; the local instance presents first-load owner setup and must remain private until authenticated.
7. **MEDIUM — scale and backlogs.** A five-minute schedule scans newest 40 documents and processes up to 6 eligible contacts in a batch. At significant lead volume older retries can fall beyond the scan window; use durable cursor/queue before scaling, and monitor n8n executions and blocked notification states.
8. **MEDIUM — Graph accepted is not inbox delivery.** Outlook success/Graph 202 means accepted by provider. Confirm a new synthetic consented lead in Firestore, accepted state, and real receipts or Exchange message trace across all four mailboxes before calling this live.
9. **MEDIUM — test isolation.** Local CLI import was INACTIVE, n8n DB was backed up, and a hash over Lina's workflow row before and after import proved the original workflow unchanged. Credential inventory was 0 and did not change. Cloudflare Worker alternative GH-25 was not deployed, so no dual sending path is active.

## Verdict
**Scoped quality PASS**, based on 81/81 repo tests, TypeScript, guarded build, focused 9/9 n8n contract/executable Code tests and real n8n v2.39.6 CLI import. **Production NOT PASS**: OAuth credentials, authenticated n8n editor access, durable uptime, Graph send and four mailbox receipts missing. IBM Granite inference was not run; review is source-based and adversarial.
